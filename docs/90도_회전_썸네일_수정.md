# 90도 회전된 의뢰서 썸네일 처리 수정

## 문제 상황
90도 회전된 의뢰서 PDF에서 썸네일이 제대로 적용되지 않는 문제
- 일반 의뢰서: 정상 작동 ✅
- 90도 회전 의뢰서: 썸네일 위치/크기 오류 ❌

## 근본 원인

### 1. 이중 좌표 변환 문제
- PDF 정규화로 이미 회전이 수정됨
- 정규화된 PDF에 대해 또 다시 좌표 변환 적용
- 결과: 잘못된 좌표 계산

### 2. 처리 순서 문제
```
이전 순서 (문제):
1. 페이지 회전 확인
2. 좌표 변환 (x, y)
3. 크기 변경 (width ↔ height)  ← 이미 변경된 상태
4. 표지 처리 (비율 계산 오류)
5. 썸네일 삽입

수정된 순서:
1. 페이지 회전 확인
2. 정규화된 PDF인지 체크
3. 정규화된 PDF면 좌표 변환 건너뜀
4. 원본 크기로 비율 계산
5. 표지 처리 (올바른 비율)
6. 썸네일 삽입
```

### 3. rotation 속성 잔존
- 정규화 후에도 페이지의 rotation 속성이 90, 270 등으로 남아있음
- 새 페이지의 rotation을 명시적으로 0으로 설정 필요

## 해결 방법

### 1. 정규화 플래그 추가 (`pdf_processor.py`)
```python
# PDF 정규화 시 플래그 설정
self.is_normalized = False
if self.settings.get('pdf_normalization.enabled', True):
    normalized_path = self._normalize_pdf(order_pdf)
    if normalized_path != order_pdf:
        self.is_normalized = True  # 정규화됨 표시
```

### 2. 조건부 좌표 변환 (`pdf_processor.py`)
```python
def _insert_pdf_page_to_page(self, page, thumbnail_info, box):
    # 원본 크기 저장
    original_width = width
    original_height = height
    
    # 정규화된 PDF는 좌표 변환 건너뜀
    if rotation != 0 and not getattr(self, 'is_normalized', False):
        x, y = self._transform_coordinates(x, y, width, height, rotation, page)
        if rotation in [90, 270]:
            width, height = height, width
    elif rotation != 0 and getattr(self, 'is_normalized', False):
        self.logger.debug(f"정규화된 PDF - 회전 변환 건너뜀")
```

### 3. 비율 계산 수정 (`pdf_processor.py`)
```python
# 정규화된 PDF에서 회전 정보가 남아있는 경우
if getattr(self, 'is_normalized', False) and page.rotation != 0:
    # 원본 크기로 비율 계산 (회전 영향 배제)
    box_ratio = original_width / original_height
else:
    box_ratio = width / height
```

### 4. rotation 명시적 설정 (`pdf_normalizer.py`)
```python
# 90도/270도 회전 처리
new_page = new_doc.new_page(width=new_width, height=new_height)
new_page.set_rotation(0)  # 명시적으로 0 설정

# 180도 회전 처리
new_page.show_pdf_page(new_page.rect, doc, page_num, rotate=-rotation)
new_page.set_rotation(0)  # 명시적으로 0 설정
```
