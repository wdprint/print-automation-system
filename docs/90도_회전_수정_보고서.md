# 90도 회전 PDF 좌표 문제 수정 보고서

## 문제 상황
90도 회전된 의뢰서 PDF에서 썸네일과 QR 코드가 잘못된 위치에 삽입되는 문제가 발생했습니다.

## 원인 분석

### 1. 잘못된 좌표 변환 로직
`_transform_coordinates` 메서드에서 PDF 정규화가 활성화되어 있으면 무조건 좌표 변환을 건너뛰도록 구현되어 있었습니다:

```python
# 문제가 있던 코드
if self.settings.get('pdf_normalization.enabled', True):
    return x, y  # 무조건 원본 좌표 반환
```

### 2. 정규화 후에도 남아있는 회전 정보
PDF를 정규화해도 페이지의 `rotation` 속성이 여전히 90, 180, 270 등의 값을 가질 수 있습니다. 정규화는 시각적으로 페이지를 올바른 방향으로 만들지만, 메타데이터는 유지될 수 있습니다.

## 해결 방법

### 1. 좌표 변환 로직 수정 (`pdf_processor.py`)
회전 각도가 0이 아닌 경우에만 좌표 변환을 적용하도록 수정:

```python
def _transform_coordinates(self, x, y, width, height, rotation, page):
    # 회전이 없으면 좌표 변환 불필요
    if rotation == 0:
        return x, y
    
    # 회전이 있는 경우 좌표 변환 적용
    if rotation == 90:
        new_x = y
        new_y = page.rect.width - x - width
        return new_x, new_y
    # ... 나머지 회전 각도 처리
```

### 2. 정규화된 PDF 사용 확인
정규화된 PDF가 실제로 사용되도록 명시적으로 교체:

```python
if self.settings.get('pdf_normalization.enabled', True):
    normalized_path = self._normalize_pdf(order_pdf)
    if normalized_path != order_pdf:
        self.logger.info(f"정규화된 PDF 사용: {normalized_path}")
        order_pdf = normalized_path  # 정규화된 PDF로 교체
```

### 3. PDF 페이지 삽입 시 좌표 변환 적용
썸네일 PDF를 삽입할 때도 회전 확인 및 좌표 변환 적용:

```python
def _insert_pdf_page_to_page(self, page, thumbnail_info, box):
    # 페이지 회전 확인 및 좌표 변환
    rotation = page.rotation
    if rotation != 0:
        x, y = self._transform_coordinates(x, y, width, height, rotation, page)
        if rotation in [90, 270]:
            width, height = height, width
```

### 4. 디버깅 로그 추가
회전 상태 추적을 위한 상세한 로그 추가:

```python
self.logger.info(f"페이지 회전 {rotation}도 감지 - 좌표 변환 적용")
self.logger.debug(f"90도 회전: ({x}, {y}) -> ({new_x}, {new_y})")
```

## 예상 결과

1. **90도 회전된 PDF**: 
   - 정규화 과정을 거쳐 올바른 방향으로 변환
   - 썸네일과 QR 코드가 정확한 위치에 삽입

2. **정상 PDF**:
   - 회전이 없으므로 좌표 변환 없이 처리
   - 기존과 동일하게 정상 작동

## 성능 영향

- 회전 감지 및 좌표 변환은 매우 빠른 연산이므로 성능에 미치는 영향은 미미합니다
- 디버깅 로그는 INFO/DEBUG 레벨로 설정되어 프로덕션 환경에서는 비활성화 가능
